# Engineering verification guide

This project provides **preliminary research/education engineering tools**, not a code-compliant building design package. Numerical claims are generated by deterministic Python/OpenSeesPy methods. The Ollama model may interpret text and explain results but is not the authority for computed capacities.

## Standards and explicit scope

| Feature | Code context | Implemented | Not implemented |
| --- | --- | --- | --- |
| Representative LRFD combinations | ASCE/SEI 7-22 Ch. 2 | Selected factor maps for D, L, S, W, EX, EY and ± signed lateral effects | Full LRFD/ASD suite, Lr/R, seismic rho/Ev, orthogonal effects, overstrength, load-duration special cases |
| Seismic drift | ASCE/SEI 7-22 §12.12.1 Table 12.12-1 | X/Y/resultant pairwise drift magnitude, Cd/Ie amplification, category-specific limit, utilization | Response-spectrum directional envelope, accidental torsion, orthogonal directions, diaphragm rotation effects and complete seismic analysis |
| Geometric second order | AISC 360-22 Chapter C context | OpenSees 3D elastic PDelta transformation and first-order displacement comparison | Full direct analysis method, imperfections, reduced stiffness, P-δ along members, rigorous nonlinear stability |
| Seismic P-delta screening | ASCE 7-22 §12.8.7 context | Dimensionless θ = P δ_elastic / (V h), amplification where admissible | Per-story seismic P/V derivation, explicit drift factors, complete code second-order verification |
| Steel interaction | ANSI/AISC 360-22 H1-1 | Pr/Pc and Mx/Mcx+My/Mcy interaction using correct H1-1a/b branch | Automatic Pr, Pc, Mcx, Mcy derivation, member slenderness and bracing, Chapter C stability and full detailing |
| Steel shape selection | Existing AISC 360-16-inspired routines | Limited W-shape library candidate selection for flexure, shear and axial compression | Fully validated 2022 code design, all shapes and limit states |
| Member serviceability | AISC 360-22 Chapter L context | User-selected L/N comparison | A universal code-specified L/N limit; other serviceability requirements |

A PASS reports only that the **supplied inputs and selected acceptance criterion** satisfy the implemented equation. It never means the structure is code compliant.

## UI workflow

1. Start a 3D frame project and apply material, section, supports and loads with consistent SI units.
2. For selected load combinations, click **Analyze → ASCE Combos**, read the warnings and review generated factors before using them. The templates only reference currently present load cases.
3. Select an active combination. Optionally enable **P-Delta (3D)** to compare geometric and first-order response.
4. Click **Analyze** and inspect the report and selected result combination.
5. Choose **Code Review**. For seismic drift, select X or Y, provide Cd, Ie, risk category, construction class and confirm the drift case is a valid first-order elastic seismic result.
6. For steel H1, supply required demands and *independently determined* available strengths. For deflection, select an appropriate project-specific L/N ratio.
7. Export results and document assumptions. Keep model hash and timestamp with the engineering calculation.

## Ask Ollama for design

The **Steel Design** quick prompt and regular chat use the existing Ollama client. The LLM selects an operation from a typed schema; Python rejects numeric values that were not literally present in the submitted question. All required design loads and capacities must be given. If the LLM cannot be reached, an explicit `key=value` parser can still process a limited request.

```text
Design steel beam Mu=220 kN-m, Vu=80 kN, Lb=3 m, Fy=345 MPa
Design steel column Pu=400 kN, KL=4 m, Fy=345 MPa
Check steel H1 interaction Pr=20 kN, Pc=100 kN, Mrx=30 kN-m, Mcx=100 kN-m, Mry=10 kN-m, Mcy=100 kN-m
```

A design request returns the numerical result from Python and a downloadable Markdown trace with stated inputs, timestamp, code context, input hash and limitations. Never treat LLM-generated prose as a substitute for explicit engineering equations.

## Benchmark and regression testing

GitHub Actions runs the engineering regression suite using `python -m pytest -q tests/test_code_checks.py tests/test_engineering_extensions.py`. The new tests cover:

- X/Y displacement pairing (3, 4 and 5 mm vector benchmark).
- H1 low/high axial-ratio equation branches and invalid capacities.
- Signed lateral load-case factor maps.
- P-delta dimensionless stability coefficient (1000 kN, 12 mm, 100 kN, 3 m gives θ=0.04).
- OpenSees 3D cantilever first/second-order comparison.
- Ollama tool extraction against values literally present in the prompt, including rejection of invented capacities.

The legacy independent solver cross-validation endpoint is `POST /api/loads/cross-validation`; it compares beam/truss/frame solver implementations. These checks do not cover all structures, systems, load cases, failures, units, and nonlinear effects encountered in professional engineering.

## Outstanding engineering work

A production design engine still requires full seismic/wind load procedures, modal response-spectrum analysis with complete directional combination treatment, per-member design capacity derivations, material nonlinear behavior where required, load-case and stability consistency checks, verified 3D benchmarks, report sign-off, and user/project isolation. Independent comparison with recognized structural software and analytical benchmarks is needed before relying on results for engineering decisions.


## Local member force diagrams and coordinate-system verification

**Code correction:** OpenSees `ops.eleForce(member)` returns the global resisting-force vector. For a 3D `elasticBeamColumn`, `ops.eleResponse(member, "localForce")` returns the twelve local end actions in the I/J order `[Ni, Vyi, Vzi, Ti, Myi, Mzi, Nj, Vyj, Vzj, Tj, Myj, Mzj]`. Never interchange local and global axes when designing or interpreting results.

StructAgent now retains `global_member_forces` separately from `member_forces` (local), constructs `member_force_diagrams` for each load combination and frame member, and reports maximum absolute section actions for the selected combination. The viewer samples 41 equally spaced stations along each 3D member and supports CSV export.

For a section measured a distance x from end I of a straight elastic element with uniform local transverse loads wy and wz, the local cut-resultant convention in the application is:

```text
N(x)  = -Ni
Vy(x) = -Vyi - wy*x
Vz(x) = -Vzi - wz*x
T(x)  = -Ti
My(x) = -Myi - Vzi*x - wz*x*x/2
Mz(x) = -Mzi + Vyi*x + wy*x*x/2
```

Units are kN, kN-m, kN/m and metres as applicable. Local end action signs are those given by the OpenSees coordinate transformation. These formulas assume full-length uniform member loads, no axial distributed load, no interior point element loads, and the implemented linear-elastic element. End-equilibrium residuals are included to help detect inconsistencies. For geometric P-delta analyses, separate validation of the internal section force distribution is required.

**Reference benchmark:** a simply supported 6 m beam under a constant local `wy = -10 kN/m` load has `Vi = Vj = 30 kN`, `Mz(0) = Mz(6) = 0` and a midspan internal sagging moment `Mz(3) = 45 kN-m`. The automated benchmark checks this curve, endpoint equilibrium and other axial/shear/bending cases. The test suite also checks a real OpenSeesPy element and all diagram fields.

Official references:

- [OpenSees elasticBeamColumn element documentation](https://opensees.berkeley.edu/wiki/index.php/Elastic_Beam_Column_Element)
- [OpenSees full-span 3D local beam-uniform load definition](https://opensees.github.io/OpenSeesDocumentation/user/manual/model/pattern/PlainPatternloadcommands/eleLoad.html)

**Limitations:** output from a single selected load combination does not constitute an envelope; member section capacities, geometric imperfections, direction-dependent stability and all other code criteria require independent verification. Previous saved analysis outputs produced by older StructAgent revisions may have mislabeled global forces. Re-run those analyses under the updated solver before relying on local force tables.
